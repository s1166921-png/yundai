# 销售账号与客户归属

## 操作

1. 管理员在 `/admin/promotions` 创建销售，再打开 `/admin/sales/accounts`，使用原管理员凭据读取数据，为该销售创建唯一账号和初始密码。
2. 销售从 `/admin` 的“销售登录”进入 `/admin/sales`，使用管理员设置的密码即可进入工作台，无需首次改密。
3. 销售在“我的推广码”复制链接或下载二维码。客户从该链接提交现有融资表单后，系统保存来源销售与初始负责人。
4. 销售查看“我的客户”，可以搜索企业、联系人或电话，查看融资需求、填写资料及客户版测评结果。销售不能导出全量客户、修改审核、重试 AI、管理其他账号。
5. 管理员在“账号与客户分配”中按销售或待分配筛选客户并转交。原来源不变，历史转交记录保存在客户记录中；旧销售下一次请求失去访问权。原客户后台也显示来源/负责销售和分配状态筛选。
6. 停用账号同时停用该销售推广码，撤销全部会话；原推广页停用同样生效。重新启用不会恢复旧会话。重置密码也会撤销会话，销售使用新密码重新登录后即可进入工作台。

管理员应通过合适的私密渠道把初始密码交给对应销售，不共享管理员凭据。密码不保存到浏览器存储，数据库只保存带盐 scrypt 哈希。

销售密码长度为 8–128 个字符，创建、重置和自行修改使用同一规则。已有密码继续有效。

## 归属口径

每次提交是独立线索，不按手机号自动合并，不自动抢占旧线索。ref 取提交时当前网页地址，不跨设备或长期记忆。转发链接仍归于原推广码。

无来源、无效或停用来源进入待分配；推广存储故障也优先保存客户为待分配，并显示来源解析失败。历史记录不自动分配。来源证明提交入口，不证明访问者身份。

## 运行与发布

沿用 `MEIOU_PUBLIC_SITE_URL`、`MEIOU_PROMOTION_DB_PATH`、管理员和允许 Origin 配置。正式站点必须使用 HTTPS，并将精确正式 Origin 加入 `MEIOU_ALLOWED_ORIGINS`；不可使用通配符或信任任意转发头。反向代理需把 `/admin/sales`、`/admin/sales/accounts` 和所有 `/api/sales/*`、`/api/admin/sales/*`、`/api/admin/leads/*` 交给 Node，禁止缓存。

销售 Cookie 默认 Secure、HttpOnly、SameSite=Strict，Path=/api/sales，8 小时绝对过期。变更请求还需 CSRF Token 与允许的 Origin。管理员保留原 Basic 认证方式。

程序化本地预览可设置 `salesCookieSecure:false`，但必须同时显式启用 `allowLocalDevelopmentOrigins:true`。此选项仅供本机 HTTP 演示，正式启动不暴露关闭 Secure 的环境开关。

登录限制：直接 socket 地址每分钟 20 次，全局每分钟 200 次，同时最多执行 4 次密码派生。反向代理可能令所有销售共享来源额度，团队规模扩大前需要增加经过验证的可信代理策略及边缘限流；不能直接信任客户端 X-Forwarded-For。

需要支持 node:sqlite 的 Node，当前验证版本 24.15.0。首次打开推广库自动幂等创建账号和会话表，保留原销售 ID、二维码及统计，并清除旧账号的待首次改密标记，不修改原密码或会话。客户 JSON 保持原格式，只增加归属、状态和转交历史字段。现阶段适用单实例本地持久磁盘；多实例共享写入之前需迁移为统一事务数据库。

发布前备份客户 JSON 和一致性 SQLite 快照，核对目录 ACL、Origin、域名和路由。禁止单独热复制 SQLite 主文件而遗漏 WAL。回滚应用需保留数据，不删除新表或归属字段。本次开发交付不代表已经上线。

## 扩展空间

| 模块 | 当前职责 | 未来扩展位置 |
|---|---|---|
| sales/identityStore.mjs、passwords.mjs | 销售身份、密码、会话 | 新认证方式、密码策略、会话治理 |
| sales/http.mjs、authRoutes.mjs | 登录与请求认证 | 团队角色能力检查，保持服务端授权 |
| sales/ownership.mjs | 来源、当前负责人、转交审计 | 分配规则、团队交接 |
| sales/customerRoutes.mjs、customerProjection.mjs | 按负责人读取、显式数据投影 | 跟进记录、受限导出、字段权限 |
| sales/salesClient.mjs、accountClient.mjs | 销售与管理员交互 | 新功能入口，不改变身份协议 |

使用不可变销售 ID 关联账号和客户，姓名修改不影响关系。来源与负责人分离；客户 revision 防止并发覆盖；投影显式挑选字段，新增内部字段不会自动暴露给销售。数据库新增结构采用幂等迁移。

后续跟进记录建议独立按 leadId/accountId 存储，调用现有客户授权后读写；团队主管权限应新增能力策略并补越权测试，不简单放开全量查询。本阶段不创建未使用的角色、CRM 表或插件框架。

# 销售专属二维码与访问统计：第一版设计

日期：2026-09-22
状态：方案范围已由用户确认，本文待审阅；尚未实施产品代码。

## 目标与已确认范围

每位销售获得独立推广链接和二维码。客户打开后访问原云贷页面，后台可以按销售查看推广访问情况。第一版覆盖销售管理、二维码生成和下载、匿名访问统计。客户实名识别、微信授权、短信验证、客户归属分配和销售独立账号留待后续。

第一版由管理员统一操作，销售拿到二维码即可推广。二维码被转发后的访问仍记录为该推广码来源；不能据此证明由该销售直接接触了访问者。

## 项目基础与兼容约束

- 现有 React/Vite 首页、三步融资测评、Node HTTP API、管理员 Basic 认证和选中客户导出继续工作。
- 新功能使用独立模块，在 `server/index.mjs` 接入路由，在现有后台增加销售推广入口。
- 客户数据 `server/data/leads.json` 不迁移、不修改；推广数据独立保存。
- 保留本地现有 SEO 改动；带推广参数的首页 canonical 保持无参数首页。
- 本地文档记录的站点地址为 `https://yundai.meiouyuncang.com/`。二维码使用服务器配置的公开网站地址，不从客户端或请求 Host 推导。
- 开发在本地完成并提供预览，正式上线单独处理；开发测试不连接真实客户数据。

## 管理员操作

1. 在后台打开“销售推广”，复用管理员认证。
2. 新增销售姓名和可选内部备注；服务端生成不可变销售 ID 和不可猜测的随机推广码。
3. 列表显示姓名、启用状态、推广链接、累计访问次数、最近访问时间。
4. 支持复制链接、预览二维码和下载 PNG；二维码由本地库生成，不调用外部二维码服务。
5. 可以改名、修改备注、停用和重新启用。改名不改变链接；停用不删除历史统计。第一版不提供永久删除。
6. 可选择上海时区的起止日期查看各销售访问次数；无事件的销售显示 0。

不提供销售独立登录。管理员凭据不能分享给普通销售。

## 推广入口与访问口径

链接形式为 `https://yundai.meiouyuncang.com/?ref=<随机推广码>`，二维码编码该链接。

首页读取 ref 后，在页面可见时发送一次匿名访问事件。事件带随机 eventId，同一次页面加载的请求重试复用该 ID，后端做幂等处理。React 重复 effect 不应造成额外统计。

- 指标名称为“推广访问次数”，不是扫码人数、客户人数或独立访客数。
- 同一次页面打开最多成功计数一次；刷新、重新打开可以产生新访问。
- 普通访问不带 ref 时不计入任何销售；无效或停用的推广码也不计数。
- 单纯请求页面 HTML 不计数，可减少链接预览请求造成的误报；这不保证排除所有机器人。
- 事件时间使用服务器时间，统计起止日期统一转换为上海时区自然日。
- 上报失败不阻止首页、产品加载或融资测评；可有一次使用同一 eventId 的短延迟重试，不无限重试。
- 浏览器标识不用于宣称已确认客户身份；第一版不做跨设备追踪和设备指纹。

## 模块与数据

使用独立推广存储模块，采用 SQLite 保存销售和事件，事务保证推广码唯一与事件幂等。开发前确认 SQLite 驱动与正式运行环境兼容；本地 Node 为 v24，生产运行时需在部署准备时核验。数据库路径可配置，默认位于不提交的 server/data 下，数据库文件不通过静态路由提供。

salespeople：id、name、internalNote、referralCode（唯一）、active、createdAt、updatedAt。

promotion_events：eventId（唯一）、salespersonId、eventType（首版仅 page_view）、occurredAt。

事件不保存姓名、手机号、表单内容、完整来源 URL 或原始 IP。未来客户关联通过独立的访问/线索关联结构增加；不能把历史匿名事件追溯宣称为已确认身份。

原始事件保留 90 天；较早事件按销售和上海日期转为每日计数，归档及删除在事务内完成。累计和日期筛选统计同时覆盖每日汇总与未归档事件，避免重复计数。每日汇总结构为 salespersonId、date、pageViewCount。

## 接口边界

- 管理接口：销售列表、新增、修改、日期统计、二维码下载，均要求管理员认证。
- 公开接口：仅接收有效格式的 ref、eventId、固定事件类型；响应不包含销售备注、姓名或客户数据。
- 服务端验证长度、类型、日期范围、推广码状态；对事件接口做请求体限制和基础速率限制。
- 管理写入保持现有严格 Origin/CORS 检查；数据响应使用 no-store。
- 管理员名称和备注按文本安全渲染，不能插入可执行 HTML。
- 推广码只能标记来源，不能作为任何管理或客户资料访问凭证。
- 公开站点 URL 未正确配置时，后台明确提示配置缺失，禁止生成误指向 localhost 的正式推广二维码。

## 页面与异常反馈

后台新增独立销售推广区，沿用现有布局和配色。销售表格、添加/编辑表单、日期筛选、二维码预览构成全部界面。

创建成功后可直接复制链接或下载二维码。重复姓名允许存在但有独立 ID。提交期间按钮禁用；错误保留已填内容。认证失败、统计读取失败、二维码生成失败均显示具体可操作提示。公开网站不向客户暴露推广存储错误。

首页新增简短的推广来源统计说明，说明仅记录匿名来源访问，具体客户识别属于后续范围。

## 验收标准

1. 两位销售生成不同推广码，二维码解码结果与对应完整链接一致。
2. A 的链接成功上报只增加 A 的计数；B 同理。
3. 同 eventId 重试只计一次；并发写入和服务重启后计数正确。
4. 无来源、无效码、停用码不增加有效销售统计，仍可浏览网站。
5. 上海日期边界、零访问销售、原始事件归档前后统计正确。
6. 未认证请求不能读取或修改销售、下载管理二维码、查看统计。
7. 名称/备注中的 HTML 按普通文本显示；公开接口不泄露内部资料。
8. 浏览器实际验证新增、复制、二维码下载、日期筛选、停用流程；验证首页上报失败不影响原表单。
9. 运行相关自动化测试、原有测试套件和现代/旧版浏览器构建；报告未完成的设备实测。
10. 仅使用合成销售与合成访问数据，不改动真实客户数据或部署环境。

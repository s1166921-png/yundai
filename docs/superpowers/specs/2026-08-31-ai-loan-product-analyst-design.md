# 美鸥 AI 贷款产品分析师升级设计

日期：2026-08-31  
状态：用户已确认  
范围：本地开发与内部验证，不部署生产服务器

## 1. 目标

将现有“规则匹配 + AI 文案整理”升级为“美鸥 AI 贷款产品分析师”。客户提交精简经营信息后，系统立即生成一份包含参考融资区间、建议期限、适配理由、关键假设、敏感性分析和资料建议的专业初步报告。

升级后的核心价值不是让模型自由猜测金额，而是让 DeepSeek 在产品规则允许的候选场景中完成专业判断：

1. 本地规则引擎确认产品准入、产品上限和期限边界。
2. 本地测算引擎为每款产品生成可验证的保守、基准和积极场景。
3. DeepSeek 根据脱敏经营因素选择最合适的场景，并解释原因。
4. 服务端校验 AI 选择未突破产品边界后，生成客户可见报告。
5. 专业顾问在后台查看完整依据并进一步复核。

客户立即看到“AI 初步参考区间”；顾问后台看到完整分析、假设、缺失数据和复核入口。

## 2. 方案选择

### 2.1 已选择：规则边界 + 场景测算 + AI 分析

该方案兼顾专业表现、可解释性和风险控制。DeepSeek可以对融资能力、期限和产品组合做真实判断，但只能从服务端提供的候选场景和代码中选择，不能输出任意金额、期限、利率或产品。

### 2.2 未选择：DeepSeek 直接生成金额和期限

优点是开发快、报告看起来灵活；缺点是模型可能编造产品参数、突破额度上限、引用未提交事实，也无法稳定复现。该方案不适合贷款产品分析。

### 2.3 未选择：完全本地规则报告

优点是稳定；缺点是只能输出机械结论，难以结合经营阶段、资金用途和资料完整度形成专业分析，无法体现 AI 的价值。

## 3. 决策权边界

### 3.1 产品规则引擎负责

- 产品基础准入、排除和排序。
- 币种、产品额度上限、期限选项和参考利率。
- 已满足、未满足及待补充条件。
- 额度公式中可验证的产品参数。
- 顾问需要核验的原始资料类别。

### 3.2 融资场景引擎负责

- 将产品额度公式、客户需求和产品上限组合成候选区间。
- 为资料完整的产品生成保守、基准、积极三个场景。
- 为资料不足的产品返回“暂不能量化”，而不是伪造金额。
- 计算每个场景的金额范围、期限选项、参考定价和依赖假设。
- 保证所有候选场景均位于产品目录允许边界内。

### 3.3 DeepSeek 负责

- 判断客户的经营阶段、资金用途和现金流特征。
- 在允许的候选场景中选择最符合当前证据的融资区间。
- 在产品允许的期限选项中选择建议期限。
- 解释额度处于区间当前位置的原因。
- 识别可能使额度上调或下调的关键变量。
- 给出产品组合、资料准备和顾问复核重点。
- 输出分析可信度等级及其原因。

### 3.4 DeepSeek 不得

- 修改产品准入状态或排序。
- 新增规则引擎未返回的产品。
- 输出候选场景之外的金额、期限、利率或币种。
- 把意向金额直接当作可审批金额。
- 引用客户未填写的经营事实。
- 输出“可批”“已获批”“保证通过”等承诺。
- 在资料不足时用行业常识补造财务数据。

## 4. 产品额度场景

### 4.1 通用生成规则

每款产品的场景生成器输出：

```json
{
  "productId": "catalog-product-id",
  "eligibilityStatus": "eligible",
  "amountScenarios": [
    {
      "scenarioCode": "conservative",
      "currency": "USD",
      "minimum": 1200000,
      "maximum": 1600000,
      "assumptionCodes": ["stable-store", "collections-unverified"]
    },
    {
      "scenarioCode": "balanced",
      "currency": "USD",
      "minimum": 1600000,
      "maximum": 2000000,
      "assumptionCodes": ["stable-store", "requested-amount-within-cap"]
    }
  ],
  "termOptions": ["90_days", "revolving"],
  "pricingReference": "9%-11%",
  "missingEvidenceCodes": ["twelve-month-collections", "current-debt"]
}
```

金额场景由服务端生成并版本化。所有系数必须有业务定义、测试和变更记录，不能来自模型自由发挥。

### 4.2 已有产品的量化能力

- **微众跨境电商数据贷**：以近 12 个月月均回款的 1 至 3.5 倍生成候选区间，最高 2000 万元；期限为 4+5 或 3+6，额度有效期 1 年。
- **平安外贸物流贷**：按年销售额乘行业系数与税票核额综合测算，最高 500 万元；期限最长 36 个月。
- **联易融 Amazon SC**：按合格店铺数和单店 300 万美元上限形成额度边界，再结合融资需求、店铺 GMV、回款稳定性和资料完整度生成候选区间；期限为 90 天或循环使用。
- **平安橙业贷**：当前只能给出 5 万至 300 万元产品范围。补充税金到额度的核额公式前，AI不得进一步缩窄区间。
- **招商银行经营贷**：缺少基础系数、附加系数和期限参数，当前只输出产品方向及“待银行最终核定”。
- **联易融 Amazon VC 与 B2B 保理**：缺少应收账款融资比例参数。补充比例前只输出方向、期限和所需资料，不生成虚假额度。

## 5. 精简数据采集

继续采用条件式表单，不把所有产品字段一次性展示给客户。优先复用现有经营字段，并只在相关场景出现时增加影响额度判断的字段。

### 5.1 通用核心字段

- 主营业务场景。
- 企业注册地区和成立时间。
- 年营收或平台 GMV。
- 本次融资需求、币种和资金用途。
- 现有贷款余额区间。
- 是否存在当前逾期或重大信用司法负面。
- 联系方式和数据使用同意。

### 5.2 条件字段

- Amazon：近 12 个月回款、店铺数、退款率、库存周转、店铺状态、回款账户安排。
- 外贸物流：进出口额、行业、税票核额、营收、负债率。
- B2B 应收：应收账款余额、账期、买方交易历史、买方国家与账户管理安排。
- 税务经营：纳税及发票数据、授信银行数量和现有负债。

非必需字段不显示星号。客户可以先提交基础资料；缺失字段会降低可信度并扩大区间，而不是阻塞所有报告。

## 6. AI 输入与输出契约

### 6.1 脱敏输入

DeepSeek只接收：

- 经营场景类别和企业地区类别。
- 经营时长、GMV、营收、回款、负债和需求的区间化结果。
- 产品 ID、准入状态和服务端候选场景代码。
- 服务端允许的期限代码、原因代码、假设代码和敏感性代码。
- 资料完整度等级和待确认资料类别。

不得发送企业名称、联系人、手机号、客户编号、银行账号、真实买方名称、原始合同、流水、征信或自由文本。

### 6.2 模型输出

新契约版本为 `meiou-ai-analyst-v3`。模型返回代码，不返回任意金融数字：

```json
{
  "schemaVersion": "meiou-ai-analyst-v3",
  "portfolioSummaryCodes": ["growth-stage", "inventory-funding"],
  "productAnalyses": [
    {
      "productId": "linklogis-amazon-sc",
      "selectedAmountScenarioCode": "balanced",
      "selectedTermCode": "90_days",
      "reasonCodes": ["gmv-above-threshold", "history-qualified"],
      "riskCodes": ["collections-unverified"],
      "sensitivityCodes": ["higher-stable-collections-may-increase"],
      "confidenceCode": "medium"
    }
  ],
  "preparationActionCodes": ["prepare-amazon-report", "prepare-collections"],
  "advisorFocusCodes": ["verify-store-health", "verify-current-debt"]
}
```

服务端验证产品顺序、场景代码、期限代码和所有代码白名单。任何未知、重复、越界或重排结果都会整份降级到本地确定性报告。

## 7. 客户报告

报告按以下顺序展示：

1. **综合结论**：经营阶段、资金场景和总体融资能力。
2. **AI 参考融资能力**：币种、参考区间、建议期限、参考定价、匹配程度和可信度。
3. **区间形成原因**：产品上限、经营证据、客户需求和缺失资料。
4. **优先产品分析**：每款产品的额度、期限、定价、适配理由和待确认项。
5. **备选产品分析**：解释为什么是备选以及与第一产品的区别。
6. **敏感性分析**：哪些变化可能导致额度上调、下调或产品失效。
7. **行动建议**：下一步需要准备的资料和可执行动作。
8. **隐私与合规提示**：说明脱敏范围、顾问复核和非授信承诺。

报告不展示内部提示词、模型 Token、规则原文、内部评分、顾问备注或未验证的客户事实。

## 8. 顾问后台

后台客户详情新增“AI 专业分析”区域：

- 本地规则给出的额度边界和产品上限。
- 三个候选场景及其公式版本。
- DeepSeek选择的场景、期限、理由、风险和可信度。
- 缺失数据对区间宽度的影响。
- 顾问复核状态、内部备注和调整理由。
- 重新生成 AI 分析的受控入口。

顾问可以将状态更新为待复核、复核中、已复核或需补资料。第一阶段不允许顾问直接修改产品规则和计算公式，避免后台操作改变全局产品逻辑。

## 9. 失败与降级

- DeepSeek未配置、超时、限流、返回非法 JSON 或违反契约时，客户仍得到本地规则报告。
- 场景引擎缺少必要输入时，显示“补充资料后可量化”，不显示虚假数字。
- 产品目录缺少期限或核额公式时，明确显示“待银行最终核定”。
- AI生成失败不影响客户记录保存、后台查看或Excel导出。
- 客户报告不得暴露提供方错误、密钥、完整响应或内部错误类别。

## 10. 版本与兼容

- 产品目录、额度场景策略、AI输入、提示词和输出契约分别版本化。
- 新报告使用 `ai-analyst-v3`，历史 `v2` 报告继续可读。
- 后台可按规则版本和AI分析状态筛选。
- 第一阶段仅在本地启用，不修改线上服务器。
- 验收覆盖主流桌面端和现代手机端，不再进行旧款 iPhone 专项验证。

## 11. 测试与验收

### 11.1 自动测试

- 每款产品的额度场景边界和期限选择。
- AI永远不能突破产品上限、客户需求上限或币种限制。
- 缺少关键资料时不得生成单点额度。
- 非准入产品不得被AI提升为推荐产品。
- 模型不得新增产品、修改顺序或返回未知代码。
- 个人身份和联系方式不得进入模型请求、日志或前端包。
- DeepSeek失败、超时、限流和契约违规时正确降级。
- 历史报告、后台复核、Excel选择导出和CORS行为保持兼容。

### 11.2 场景验证

至少覆盖：

- Amazon SC资料完整与资料不足。
- 微众回款高、中、低三个场景。
- 平安物流批发零售和加工制造场景。
- 超出产品上限、需求金额过高和币种不一致。
- 当前逾期、拒绝账户管理和产品不准入。
- VC、B2B、招商和橙业贷暂不能精确量化。

### 11.3 浏览器验收

- 1440像素桌面和390像素现代手机视口。
- 报告区间、期限和表格不溢出、不重叠。
- 加载、成功、降级、待补资料和顾问复核状态清晰。
- 使用真实本地API完成一次客户提交、AI报告、后台复核和选择导出。

## 12. 成功标准

- 客户可以理解“为什么是这个额度区间”，而不只是看到产品名称。
- DeepSeek对经营阶段、产品组合、期限和敏感性提供明显的专业增量。
- 所有金额和期限均可追溯到服务端候选场景，模型无法自由编造。
- 资料不足时报告诚实表达不确定性，并给出缩小区间的下一步动作。
- 顾问能在一个后台视图中看到规则依据、AI判断和复核重点。
- DeepSeek不可用时，核心匹配、报告、后台和导出仍正常工作。

## 13. 非目标

- 不替代银行授信审批或征信审查。
- 不预测最终放款概率或承诺通过率。
- 不把模型输出作为自动审批依据。
- 不上传原始合同、流水、征信和证件给第三方模型。
- 不在本阶段部署服务器、接入短信或发布私密报告链接。

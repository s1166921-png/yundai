# 销售账号与客户归属设计

状态：待用户审阅。已确认销售仅能查看自己负责的客户，管理员可查看全部。此前二维码版本已完成，本阶段尚未实现。

## 目标与方案

沿用 /admin 入口和现有融资表单。管理员创建销售独立账号，关联已有销售推广 ID；客户从专属链接提交资料，服务端记录来源和负责人；销售登录后查看自己负责的客户具体资料。

推荐在现有 Node 后台增加身份与权限模块，复用现有客户文件及推广 SQLite。独立建设销售后台需要重复维护列表与登录；直接共享管理员账号无法隔离客户，均不采用。无需接入外部 CRM。

## 第一版业务规则

- 管理员查看全部客户，创建账号、重置密码、停用账号、分配或转交线索。
- 销售查看自己当前负责的客户的姓名、联系方式、企业信息、融资需求和客户测评报告；可取得自己的推广链接和二维码。
- 本阶段销售只读客户资料；不提供销售批量导出、删除、审核修改或 AI 重试权限。既有管理员功能保留。
- 客户记录增加来源销售 sourceSalespersonId 和当前负责人 assignedSalespersonId。来源在提交时确定，不随转交改变。转交记录操作者、前后负责人和时间。
- 第一版按每次表单提交的线索进行归属，不以手机号自动合并客户，也不宣称手机号已验证。同一人多次提交可形成多条线索，已有线索不因新提交改变负责人。
- 默认按提交时当前页面的有效 ref 归属。不跨设备识别，不跨浏览器或长期保存来源。转发链接仍归于原推广码。
- 有效且启用的销售链接：来源和初始负责人均为该销售。普通、无效或停用链接：线索进入管理员待分配列表。
- 未归属的历史客户仍只对管理员可见，由管理员手动分配。管理员转交后，原销售下一次请求不能再读取该线索；此前已经看到的信息无法从其记忆或已保存副本中撤回。
- 销售账号停用立即失去访问权限并撤销会话；同时停用关联推广码。历史线索保留，管理员可转交；启用操作明确恢复账号及推广状态。

## 认证与权限

管理员保留原有管理认证，新增销售账号密码登录接口，账号与不可变销售 ID 绑定。销售密码通过随机盐和 scrypt 保存哈希，不存明文。初始密码由管理员设置，销售首次登录需修改；重置密码与停用使旧会话失效。

销售会话使用高熵随机令牌，服务端只存令牌哈希、账号 ID 和失效时间，浏览器使用 HttpOnly、SameSite Cookie，正式 HTTPS 环境设置 Secure。会话绝对有效期 8 小时，退出撤销。登录限速，错误提示不透露账号是否存在。状态变更请求检查 Origin 和 CSRF；本地开发 Cookie 例外必须显式限定开发环境。

每次销售请求均在服务端验证账号状态、会话与客户负责人。列表、详情和统计都先按负责人筛选；禁止先发送全部客户再由前端隐藏。销售无法通过修改客户 ID、过滤参数或直接调用管理员导出、审核、AI 重试及推广管理接口越权。无权访问的客户统一返回不泄露是否存在的响应。

## 数据与接口边界

沿用客户 JSON 文件，不迁移历史客户内容。新增归属和转交记录与客户在现有串行写入队列中一起原子保存，使用已有 revision 机制处理并发冲突。缺失字段视为未分配。

账号、会话表通过幂等迁移加入推广 SQLite，保留现有推广 ID、二维码及统计。账号不存入客户文件。新增身份模块负责登录及会话，归属模块负责 ref 校验及客户授权，页面复用展示逻辑而不复用管理员权限。

公共表单只接受 ref，不信任客户端提交的销售姓名、负责人或角色。来源解析失败时仍保存客户为待分配，并标记解析失败供管理员处理；不得静默将其指派给任意销售。公开提交响应不返回内部归属、账号或审计数据，AI 请求也不增加这些字段。

保留匿名访问与实名提交两套指标，不能把历史匿名访问自动补认成该客户。存储故障时销售读取失败关闭，禁止退回管理员或全量数据视图。

## 页面

/admin 提供明确的管理员与销售登录入口。管理员客户列表增加来源销售、负责销售和待分配筛选，详情提供转交；销售界面显示“我的客户”和“我的推广码”，不展示全公司客户数量及其他销售资料。销售账号管理与已有销售推广管理衔接。

## 验收

以两个销售账号和合成客户验证：各自链接提交后各自可见；无 ref 待分配；停用码不分配；历史数据正常读取；同手机号重复提交不覆盖旧归属；转交前后读取权限立即变化。

测试直接篡改 ID、跨销售查询、访问管理员导出/审核/重试、过期会话、退出、账号停用和密码重置、CSRF、SQLite 故障、并发提交与转交。验证公开响应及 AI 输入不泄露新增内部字段，保持原表单与管理员功能回归通过。浏览器演示使用隔离数据。

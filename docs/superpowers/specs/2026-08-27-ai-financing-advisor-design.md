# 美鸥 AI 融资顾问第一阶段设计

日期：2026-08-27  
状态：已确认，待实施计划  
范围：本地开发与内部验证，不部署生产服务器

## 1. 目标

将现有产品匹配能力升级为“美鸥 AI 融资顾问”。客户提交精简经营信息后，系统立即生成一份有依据、可解释、待专业顾问复核的初步融资报告。

本阶段验证三个核心假设：

1. 客户是否愿意完成精简经营信息填写。
2. AI 初步报告是否能提高客户继续咨询的意愿。
3. 规则匹配与 AI 解释是否能帮助顾问更快完成后续判断。

核心信任表达为：

- 有依据：每项推荐说明匹配原因和待确认条件。
- 少暴露：模型只接收脱敏后的经营字段。
- 有人负责：结果明确标注为 AI 初步分析，等待专业顾问复核。

## 2. 已确认的产品边界

### 2.1 本阶段包含

- 使用现有规则引擎完成产品准入、排序和额度逻辑。
- 通过服务端调用 DeepSeek 官方 API。
- 使用 `deepseek-v4-pro` 生成经营分析和客户友好的解释。
- 客户提交后立即展示 AI 初步报告。
- 客户报告展示依据、待确认事项和资料准备建议。
- 后台展示 AI 报告、顾问内部备注和独立复核状态。
- DeepSeek 调用失败时自动降级为本地模板报告。
- 在首页增加“美鸥 AI 融资顾问”的可信服务表达。

### 2.2 本阶段不包含

- 短信发送、短信验证码或私密报告链接。
- 顾问编辑并发布完整客户报告。
- 客户上传合同、征信、流水、证件或其他原始文件。
- 模型直接决定产品准入、额度、费率或期限。
- 模型微调、蒸馏或 Hugging Face 自托管。
- 生产服务器、域名、DNS 或线上数据迁移。

后续阶段可增加顾问发布完整报告、阿里云短信通知和七天有效私密链接。该能力不属于本设计的实施范围。

## 3. 产品定位与页面表达

对外品牌统一为“美鸥 AI 融资顾问”。DeepSeek 是底层技术提供方，不作为页面主品牌或合作背书展示。

推荐首屏文案：

> 先读懂经营，再匹配融资
>
> AI 梳理企业经营信息，结合产品准入规则生成融资方向，由专业顾问进一步复核。

首页展示四段真实处理链路：

1. 经营信息
2. 产品规则核对
3. AI 解释分析
4. 顾问专业复核

页面不得使用“AI 秒批”“百分百获贷”“提高通过率”等无法证明的承诺。

## 4. 客户体验

### 4.1 提交前

AI 服务区采用“透明决策舱”视觉方向，延续清透紫青蓝配色。动画用于说明真实处理步骤，不使用纯装饰性的长时间等待或虚假进度。

页面显示三个信任点：

- 每个结论都有经营依据。
- AI 仅分析脱敏经营字段。
- 结果由专业顾问进一步复核。

主按钮文案为“开始 AI 融资分析”，直接进入现有精简表单。

### 4.2 生成过程

提交后按实际处理状态依次显示：

1. 正在整理经营信息
2. 正在核对产品准入条件
3. 正在生成初步分析

快速完成时，动效总时长控制在约 1 秒；真实请求较慢时显示当前状态。系统尊重 `prefers-reduced-motion`，旧版浏览器使用无动画降级。

### 4.3 AI 初步报告

报告采用渐进式信息结构：

1. **状态栏**：AI 初筛完成，专业顾问待复核。
2. **经营判断**：用两至三句话说明经营阶段、资金场景和融资特点。
3. **优先产品方向**：展示规则引擎给出的一个至三个产品。
4. **为什么匹配**：每个产品最多展示三条已提交数据对应的依据。
5. **仍需确认**：列出顾问或证明材料需要核验的条件。
6. **融资准备清单**：给出下一步需要准备的材料和行动建议。
7. **隐私说明**：说明联系方式和企业身份信息未发送给模型。
8. **合规提示**：结果仅供融资准备参考，不构成授信或放款承诺。

客户报告不展示内部评分、置信分、提示词、完整产品规则或顾问内部判断。

## 5. 决策权边界

系统采用“规则引擎定结论、DeepSeek 做解释、顾问完成复核”的混合架构。

### 5.1 规则引擎负责

- 产品准入与排除。
- 产品排序。
- 参考额度、币种、费率和期限的可展示边界。
- 已满足、未满足和待补充条件。
- 顾问待核验字段。

### 5.2 DeepSeek 负责

- 将结构化经营事实整理成自然语言。
- 解释推荐方向与客户信息之间的关系。
- 汇总待确认事项。
- 生成融资准备建议和顾问跟进重点。

### 5.3 DeepSeek 不得

- 新增规则引擎未返回的产品。
- 修改产品顺序或准入状态。
- 自行生成额度、费率、期限或审批结论。
- 引用客户未填写的事实。
- 输出“已获批”“保证通过”等承诺性表述。

服务端必须在展示前验证这些不变量。模型输出不满足约束时直接降级，不尝试向客户展示部分不可信内容。

## 6. 数据流与组件边界

### 6.1 提交流程

1. 浏览器向现有 `POST /api/leads` 提交客户资料。
2. 服务端完成字段验证、标准化和规则匹配。
3. 服务端先持久化客户记录，并将 AI 状态设为 `pending`。
4. `AiAnalysisInputBuilder` 从规则结果构造严格白名单的脱敏分析包。
5. `DeepSeekClient` 从服务端环境变量读取密钥并调用官方 API。
6. `AiReportValidator` 校验固定 JSON 结构和业务不变量。
7. 校验成功后保存 AI 报告；失败或超时则由 `FallbackReportBuilder` 生成模板报告。
8. 服务端返回客户安全的匹配结果和初步报告。

AI 调用默认超时为 12 秒，并允许通过服务端环境变量调整。客户记录的保存不能依赖 AI 调用成功。

### 6.2 组件职责

- `AiAnalysisInputBuilder`：脱敏、区间化和字段白名单。
- `DeepSeekClient`：认证、超时、限流错误和官方 API 调用。
- `AiReportPrompt`：版本化系统指令和输出 JSON Schema。
- `AiReportValidator`：结构校验、事实校验和产品目录校验。
- `FallbackReportBuilder`：完全本地、确定性的替代报告。
- `AiReportPresenter`：将客户安全报告映射成透明决策舱 UI。
- `AdvisorReviewStore`：保存复核状态、内部备注和更新时间。

这些模块通过结构化对象通信，模型客户端不读取完整客户记录，前端不接触 API Key。

## 7. 脱敏与隐私

发送给 DeepSeek 的分析包只允许包含：

- 主营融资场景类别。
- 注册地区类别和企业类型类别。
- 经营时长区间。
- 营收、GMV、交易额或意向金额区间。
- 融资币种与资金用途。
- 平台经营事实的枚举或布尔结果。
- 是否接受回款账户安排。
- 规则引擎产生的已满足条件、待确认条件和资料类别。

不得发送：

- 企业完整名称、统一社会信用代码或后台客户编号。
- 联系人、手机号、身份证件或银行账户。
- 客户和供应商真实名称。
- 原始合同、发票、流水、征信和证件。
- 浏览器会话、IP 地址或可反向识别客户的组合标识。

自由文本不得原样进入模型。需要用于分析的自由文本必须先映射为服务端控制的类别或枚举。发送前的白名单对象应当可独立测试。

现有数据使用同意文案需要明确说明：系统会将脱敏后的经营字段用于第三方 AI 辅助分析，联系方式和企业身份信息不会发送给模型。

## 8. 模型调用与输出契约

模型配置全部来自服务端环境变量：

- `DEEPSEEK_API_KEY`
- `DEEPSEEK_BASE_URL`，默认 `https://api.deepseek.com`
- `DEEPSEEK_MODEL`，默认 `deepseek-v4-pro`
- `DEEPSEEK_TIMEOUT_MS`，默认 `12000`
- `AI_DAILY_REQUEST_LIMIT`，默认 `100`

密钥不得进入仓库、前端包、日志、客户记录或错误响应。

服务端通过官方 `/chat/completions` 接口请求 JSON 输出。模型必须返回固定 JSON，至少包含：

```json
{
  "businessSummary": ["string"],
  "productExplanations": [
    {
      "productId": "catalog-product-id",
      "reasons": ["string"],
      "itemsToConfirm": ["string"]
    }
  ],
  "preparationActions": ["string"],
  "advisorFocus": ["string"]
}
```

服务端根据规则引擎结果补齐产品名称、机构、额度、费率、期限和免责声明。模型返回的同名字段一律忽略。

保存的 AI 元数据仅包括提供方、模型名、提示词版本、生成时间、耗时、Token 用量、成功或降级状态及错误类别。不得保存完整模型请求、完整响应或 API Key。

## 9. 顾问后台

产品匹配状态与顾问复核状态分开保存。

复核状态为：

- `pending`：待复核
- `in_review`：复核中
- `reviewed`：已复核
- `needs_information`：需要补充信息

后台客户详情展示：

- 客户经营信息。
- 规则引擎推荐和排除结果。
- AI 初步报告。
- AI 使用的脱敏字段类别。
- 顾问待核验事项。
- 建议跟进问题。
- 顾问内部备注。
- 复核状态及更新时间。

第一阶段不允许编辑客户经营数据、规则结果或客户可见报告。顾问只可修改内部备注和复核状态；管理员可对失败或长时间停留在 `pending` 的 AI 任务执行一次受限重试。暂不提供完整报告编辑、客户发布或短信发送。

## 10. 错误处理与降级

- API 未配置：使用本地模板并记录 `not_configured`。
- 请求超时：终止调用，使用本地模板并记录 `timeout`。
- 限流或余额问题：使用本地模板并记录归一化错误类别。
- 非 JSON 或结构错误：拒绝模型结果并降级。
- 产品、金额或事实越界：拒绝模型结果并降级。
- 客户连接中断：已保存客户记录不得丢失。
- 服务重启后仍为 `pending` 的记录：后台明确显示，可由管理员执行受限重试；本阶段不引入独立消息队列。

降级报告不得伪装成模型生成内容。客户状态应显示“智能匹配结果已生成，AI 扩展分析暂不可用，专业顾问待复核”，并继续提供完全来自规则引擎的匹配依据和资料清单。

公开错误响应不得包含模型原始错误、提示词、密钥、内部规则或客户数据。

## 11. 可观测性与费用控制

记录以下非敏感指标：

- 调用次数、成功率和降级率。
- 请求耗时和超时次数。
- 输入与输出 Token 用量。
- 模型和提示词版本。
- 输出契约失败类别。
- 顾问复核状态变化。

设置每日调用上限。达到上限后继续接收客户信息并使用本地模板，不影响核心业务。日志中不记录完整脱敏包，因为区间组合仍可能具有重识别风险。

## 12. 验收与测试

### 12.1 规则和报告测试

- 至少 30 组脱敏模拟企业案例覆盖全部产品。
- 规则引擎推荐与预期结果完全一致。
- AI 不得新增、删除或重排规则引擎产品。
- AI 不得生成目录之外的额度、费率、期限或准入条件。
- 每条客户可见依据都能映射到已提交事实。
- 客户报告不出现内部评分和顾问专用字段。

### 12.2 隐私与安全测试

- 对模型请求执行字段快照测试，确认不包含企业名称、联系人和手机号。
- 验证前端产物中不存在 API Key 和模型调用代码。
- 验证提示注入式自由文本不会改变产品结果或系统指令。
- 验证后台复核接口需要管理员认证。
- 验证公开响应不泄露模型原始错误和内部证据。

### 12.3 可靠性测试

- 覆盖成功、超时、限流、无配置、无效 JSON 和越界输出。
- 验证所有异常都返回本地模板报告且客户记录已保存。
- 验证并发提交不会覆盖客户记录或 AI 状态。
- 验证每日上限触发后自动降级。

### 12.4 用户体验测试

- 桌面、390px 和 375px 手机视口完成真实提交。
- 旧版 Safari 兼容构建和无动画降级通过。
- 状态文案不造成“银行已审批”的误解。
- 页面无水平溢出、标签错位或长文本遮挡。

## 13. 内部试用顺序

1. 使用本地模拟 DeepSeek 客户端完成自动化测试。
2. 使用官方 API 和纯模拟企业数据进行内部验证。
3. 顾问评审至少 30 份报告的正确性、可读性和跟进价值。
4. 修正提示词和展示文案，但不通过提示词改变产品规则。
5. 小范围开放真实客户，持续观察降级率和顾问反馈。
6. 第一阶段稳定后，再单独设计完整报告发布和短信交付。

## 14. 成功标准

第一阶段完成时应满足：

- 客户能完成现有精简表单并获得可解释的初步报告。
- 所有产品结论均来自确定性规则引擎。
- 第三方模型请求中不存在直接身份信息。
- DeepSeek 不可用时提交和报告仍可正常完成。
- 顾问能在后台查看报告、填写备注并更新复核状态。
- 自动化测试、生产构建和桌面/移动端真实流程均通过。
